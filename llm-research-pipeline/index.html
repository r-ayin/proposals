Four gates the chat path never passes. Each one can silently tax quality.
Gate G1

Prompt rendering

System roles, few-shot blocks and whitespace get re-serialized between your chat draft and the API call.

measure: byte-diff of rendered prompts, chat vs API
Gate G2

Schema enforcement

Strict JSON schemas coerce enums, drop nullable fields, and truncate reasoning the chat UI never asked for.

measure: field-level adherence + content fidelity per case
Gate G3

Batching

Batch endpoints change latency economics and sometimes sampling behavior; order and context windows shift.

measure: same-case batch vs single score delta
Gate G4

Model routing

Fallbacks and version pins quietly swap models; the chat UI runs the flagship while prod runs whatever answered.

measure: resolved model per request, logged and compared
02

The 2–3 hour plan

S130 min

Freeze the sample

Pick 10–20 representative cases from your eval set — or pull them from recent production logs. Nothing else changes during the session.

S240 min

Dual-path run

Same cases through the consumer chat path and the production API path. Every rendered prompt, resolved model and raw output gets logged.

S340 min

Blind diff scoring

Outputs scored side by side on two axes, without knowing which path produced which: schema adherence, and the quality of the research answers themselves.

S440 min

Rank causes, fix top two

Root causes ranked by measured impact. Config-level fixes first: schema strictness, batch flags, version pins, prompt serialization.

S530 min

Re-measure, hand over

Re-run the sample, confirm the delta, deliver the divergence map and the written checklist. You keep every artifact and script.

Capped at 3 hours. If it runs longer, we stop and you keep everything measured so far.
